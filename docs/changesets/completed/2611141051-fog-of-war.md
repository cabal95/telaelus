# Fog of War

- Status: Implemented
- Id: 2611141051-fog-of-war
- Depends-on: none

## Summary

The world starts hidden. Every map cell within sight of the player is revealed and stays revealed
for good (reveal once: there is no "seen before but not now" state, and nothing is hidden again).
Unexplored cells draw as darkness with a soft edge, and nothing in them (terrain, mountains,
rivers, fields, buildings) is drawn or can be hovered, clicked, or built on.

## Motivation

Today the whole generated world is visible from the start, so there is nothing to discover. Fog
makes exploring part of the game: the player has to walk out to find deposits and biomes. It is
also the base for the free camera (free-camera.md): panning shows only what the player has
already seen, so the camera cannot be used to scout.

## Design

### Exploration (sim)

- Each map cell has an **explored** flag, stored in its chunk (a `bool[,]` beside the terrain),
  false when the chunk is generated.
- Each step the sim reveals every map cell whose center lies within `SightRadius` of the player:
  24 units (6 map cells), a single constant in the sim so it is easy to tune. At the default zoom
  the screen shows about 28 units top to bottom and 50 across, so the revealed circle nearly
  fills the screen's height and its edge shows to the sides. Only the player reveals; buildings
  do not. Cells are revealed only when the player crosses into a new map cell (the circle is the
  same while they stay in one cell), so the cost is a few dozen cells now and then, not every
  step.
- At world start the cells around the spawn are revealed before the first frame.
- `IsExplored(mapX, mapZ)` reads it (out of bounds: false). `CellsRevealed` is raised with the
  newly revealed cells, so the presentation updates only what changed.
- Explored is world state shared by everyone (fits co-op: the team explores together).
- **Rules:** `CanPlace` also requires every footprint cell's map cell to be explored. Nothing else
  changes: harvesting needs the player within 1.5 units, which is always explored, and an
  extractor works the fields in its work area whether or not the player has seen them.
- **Which worlds have fog:** a generated world always does. The bounded test map (`initMap {}`)
  starts fully explored, so the existing scenarios and their screenshots are unchanged;
  `initMap { "fog": true }` turns fog on for it. The generated-world scenarios (`generated-world`,
  `perf-walk`) get fog; `perf-walk`'s numbers will change (fewer cells drawn), which is expected.

### Drawing (presentation)

- **Terrain:** a render tile builds placements only for explored cells. When cells are revealed,
  only the render tiles containing them are rebuilt (today any map change rebuilds every tile;
  that stays for real map changes such as `changeTiles`).
- **Granularity:** per map cell (4 x 4 units); the soft edge hides the squares.
- **Darkness:** each render tile has a fog overlay: a flat quad just above the ground, covering the
  tile, with a small mask texture (one texel per map cell, plus a one-cell border from the
  neighboring tiles so edges match across tiles) sampled with linear filtering. Unexplored is
  opaque near-black (the UI's panel color, 0.08, 0.10, 0.09) over unexplored cells and fades out
  across the outer half of the explored cells beside them, for a soft edge. Where explored cells
  meet around an unexplored cell's corner, the blend thins the dark a little inside the
  unexplored cell, where nothing is drawn, so the background would show through; a solid plane of
  the same color 3 units below the ground covers the tile too, so darkness shows there instead.
  (Forcing every unexplored cell fully dark instead left sharp notches at those corners.) A
  revealed tile is rebuilt whole, mask included; a fully explored tile has no overlay.
- **Contents:** resource field slots, mountains, river pieces, and buildings in unexplored cells
  are not drawn. (Buildings can only be placed on explored cells, so in practice only fields,
  mountains, and rivers are affected.)
- **Interaction:** the field and building under the pointer are ignored in unexplored cells, and
  the build ghost shows unplaceable there.
- The camera's background beyond built tiles is already off-screen; darkness covers everything
  inside the built area that is unexplored.

### Testing

- Sim unit tests: the spawn area starts explored; walking reveals a circle of `SightRadius`;
  revealed cells stay revealed; `CellsRevealed` fires once per newly revealed cell; `CanPlace`
  refuses an unexplored footprint; a bounded test world starts fully explored, and with fog on
  starts with only the spawn area.
- Snapshot: `world.explored` (the count of explored map cells) and `fields[i].explored` (whether
  each field's map cell is explored), enough to check that a field is hidden and then revealed
  without a per-cell query.
- A `fog` scenario: `initMap { "fog": true }`, a field placed beyond sight is not drawn and cannot
  be hovered; walking toward it reveals it; walking away leaves it revealed; screenshots of the
  soft edge at spawn and after walking.

## Code changes

- `Game.Sim`: `Chunk` holds the explored flags; `Simulation` gets `SightRadius`, `IsExplored`,
  `CellsRevealed`, the reveal on entering a new map cell and at world start, and the `CanPlace`
  check; `WorldSettings` gets `Fog` (true for generated worlds, false for the bounded test map by
  default); `SimulationDebug` gets `RevealAll` for tests.
- `TerrainView` / `TerrainTileView`: skip unexplored cells (mountains and river pieces are tile
  placements, so they need nothing more), rebuild only the tiles a reveal touches, and add each
  tile's darkness.
- `Presentation/FogOverlay.cs` (new): the overlay quad with its mask texture and shader, and the
  solid plane under it.
- `ResourceFieldViews`: leaves out fields in unexplored cells (a reveal changes a tile's shown
  fields, so its batch rebuilds).
- `BuildController`: ignores buildings and fields in unexplored cells under the pointer
  (placement is refused by `CanPlace`).
- `GameRoot`: wires `CellsRevealed`, and passes `BuildingViews` only the buildings on explored
  cells (only debug placement can put one elsewhere).
- `Debug.ResetToEmptyMap(fog)` and `Debug.RevealAll()`; the snapshot's `world.fog`,
  `world.explored`, and `fields[i].explored`.
- Testing: `initMap`'s `fog` option, the snapshot fields, the `fog` scenario, and the unit tests.

## Blueprint updates

- simulation.md and world-generation.md: the explored flag per map cell, the reveal rule, and
  which worlds have fog.
- terrain.md and resources.md: unexplored cells and fields are not drawn.
- buildings.md: placement requires explored cells.
- presentation.md: the fog overlay, per-tile rebuilds on reveal, and hidden contents.
- testing.md: `initMap`'s `fog`, the snapshot fields, and the `fog` scenario.

## Verification

- `dotnet build game.slnx`, both test suites with the new unit tests (`FogTests`) and the `fog`
  scenario: 166 sim tests and 37 integration tests pass.
- Windowed: the `fog` scenario's screenshots (the soft edge, a field appearing as the player
  nears it), and a generated world walked for a while, checking the edge looks right across
  render tile seams and the frame time stays where it was (`perf-walk`).
- Result: the `fog` screenshots and a generated world walked at two zooms show the soft edge with
  no seams across render tiles; `perf-walk` runs at about 4.5 ms a frame with 347 draw calls
  (6.7 ms and 651 before), and its worst frame fell from about 170 ms to about 130 ms.
