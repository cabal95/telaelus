# Clean Up CI Warnings

- Status: Implemented
- Id: 2611161830-ci-cleanup
- Depends-on: 2611161741-etc2-astc-import

## Summary

Clears the C# build warnings and moves every GitHub action in the workflow to a version that runs
on Node.js 24, uploading each build's zip without GitHub's second zip around it.

## Motivation

A GitHub run shows about ten C# warnings and a Node.js 20 deprecation warning. Warnings that are
always there train everyone to ignore them, so a real one gets missed. GitHub forces the old
actions onto Node.js 24 today, and they will stop working once Node.js 20 is gone from the
runners.

## Design

### C# warnings

`dotnet build Telaelus.slnx` reports twelve, in four places:

| Warning | Where | Fix |
| --- | --- | --- |
| IDE0055 formatting (x8) | `SimulationRenewables.cs` 95-102, the `BesideMountain` case block | Reformat the block the way `.editorconfig` wants (`dotnet format`). |
| IDE0055 formatting (x2) | `BuildingDetail.cs` 308-309, the comment inside the LINQ chain | Windows only; `end_of_line = lf` in `.editorconfig` (see Implementation notes). |
| CS8625 null for a non-nullable parameter | `SimulationNetwork.WouldBeOnline` passes `null` recipes to its probe `Building` | Pass `Array.Empty<Recipe>()`. The probe never reads its recipes. |
| CS0108 hides `Node.SetName` | `SaveDialog.SetName` | Delete it. Nothing calls it (scenarios type the name). |

None of these changes behavior.

### Node.js 24 actions

GitHub warns about `checkout@v4`, `setup-dotnet@v4`, `setup-python@v5` and `cache@v4`.
`upload-artifact@v4` also runs on Node.js 20 (the export job's run warns about it too). The latest
major of each runs on Node.js 24:

| Action | Now | Proposed | Breaking changes that matter here |
| --- | --- | --- | --- |
| checkout | v4 | v7 | None (Node.js 24; credentials stored in a separate file; forks blocked on `pull_request_target`, which we do not use). |
| setup-dotnet | v4 | v6 | None (Node.js 24, ESM). |
| setup-python | v5 | v7 | None (Node.js 24; the removed `pip-install` input is unused). |
| cache | v4 | v6 | None (Node.js 24, ESM). |
| upload-artifact | v4 | v7 | None by default. v7 adds `archive: false` (Decision 1). |

The minimum runner version is 2.327.1, which GitHub's hosted runners already have.

## Code changes

- `src/Telaelus.Sim/SimulationRenewables.cs`: formatting only.
- `.editorconfig`: `end_of_line = lf` for C#.
- `src/Telaelus.Sim/SimulationNetwork.cs`: the probe gets an empty recipe list.
- `src/Telaelus/Presentation/Ui/SaveDialogs.cs`: removes `SaveDialog.SetName`.
- `.github/workflows/build.yml`: the action versions above; uploads with `archive: false`, skipped
  under `act`.
- `ci/README.md`, `CLAUDE.md`: the local export command and `act`'s limits.

## Blueprint updates

- builds.md: the action versions, the artifacts' names and contents, the `.editorconfig` line
  ending, and running the export job under `act`.

## Verification

- `dotnet build Telaelus.slnx --no-incremental` reports no warnings.
- `dotnet test src/Telaelus.Sim.Tests` and `dotnet test src/Telaelus.Integration.Tests` pass.
- `act workflow_dispatch -j export` runs the test job (352 and 69 tests, no C# warnings) and the
  export job (all three builds) with the new actions, uploads skipped.
- On GitHub, a manual run shows no Node.js deprecation warning and no C# warnings.

## Decisions

1. **Upload our zips as is:** yes. `upload-artifact@v7` with `archive: false`; each artifact is
   named after its zip.
2. **Fail CI on warnings:** no. The build is clean now; nothing enforces that it stays clean.

## Implementation notes

- Two of the twelve warnings were Windows-only. `.editorconfig` set no line ending, so on Windows
  the formatter expected CRLF where `.gitattributes` checks files out LF, and it flagged two LF
  line ends in `BuildingDetail.cs`. `end_of_line = lf` for C# clears them on every platform, which
  leaves the ten GitHub reported. `BuildingDetail.cs` needed no change.
- `act`'s artifact server (0.2.97; the fix is still unreleased in 0.2.98) rejects
  `upload-artifact@v7` (nektos/act#6022), so the upload steps run only when `ACT` is unset.
  `act` runs prove the export, not the upload; the first GitHub run proves the upload.
- `act`'s build of the test projects prints about 130 `NETSDK1188` warnings (locales the
  test-platform package ships, unknown without ICU). They come from `.actrc`'s invariant
  globalization and do not happen on GitHub.
- The README, blueprint, and CLAUDE.md now run the export job locally as
  `act workflow_dispatch -j export`, since a push to `main` no longer exports.
