# Demo Save

- Status: Implemented
- Id: 2611161851-demo-save
- Depends-on: 2611161830-ci-cleanup

## Summary

A ready-made save with a working mining town: Mines, Lumber Camps, and Smelters running, Depot
trucks hauling, hubs, storage, and power, already a few minutes into its run. It loads like any
save. A generator builds it from code, so it can be made again whenever the town or the game
changes.

## Motivation

Seeing the game's later state takes a long play from a new game. A demo save shows a working town
in seconds, which helps when trying a change, showing the game to someone, or checking that a
build works.

## Design

### What the town holds

On a generated world (the starter planet, a fixed seed), around the HQ:

- **Mining:** a Drill Rig on Iron Ore, Mines on Copper Ore and Coal, and a Lumber Camp on Wood.
- **Refining:** five Smelters (four making Iron, one Copper) burning Coal and Charcoal, and a
  Charcoal Kiln.
- **Hauling:** a Depot with its full 4 trucks carrying loads to the HQ.
- **Network and storage:** Small Hubs linking everything to the HQ, a Stockyard and three
  Warehouses, and a road along the spawn's row.
- **Power (tier 1):** a Burner Generator running the Drill Rig and a Research Lab.
- **Progress:** a working stockpile, every building it has unlocked, and Material Transfer under
  way.
- **Balanced:** each hauled resource is used about as fast as it is mined, so trucks never wait on
  full storage.

Not every building or field is in it.

### Built by a generator

- `DemoTown.Build(Simulation)` (in the sim, engine-free) lays the town out with the sim's own
  tools: fields placed where the layout needs them (`Debug.PlaceField`, so the town does not
  depend on where a seed happened to put its ores), buildings placed by `Debug.PlaceBuilding`,
  roads, the stockpile, research, and Smelter recipes and fuel set the way a player would set them.
- It then runs the sim for a few game minutes (OQ4), so buffers are filling, trucks are out, and
  Smelters are mid-cycle when the save is loaded.
- A unit test builds the town and checks that it works: every building online, each Mine and Lumber
  Camp has a field in range, Smelters finished cycles, trucks delivered, and nothing is short of
  power.

### Writing the save

- The game writes it with `-- --write-demo-save` (like `--render-splash`): it builds a `GameRoot`
  over the `DemoTown` sim, waits a few frames for the views, frames the camera on the town, and
  saves it with the usual thumbnail and the presentation's part (pins and zoom). It needs a window
  for the thumbnail.
- The output is committed (see OQ1 for where). A later save format version migrates it like any
  other save; the generator is rerun only when the town itself should change.

## Decisions

1. **How it is reached:** (a), a Demo button on the main menu loading it from inside the game.
2. **Tier-1 power:** yes, a Burner Generator and a Drill Rig (and it powers the Research Lab).
3. **Fields:** placed where the layout needs them.
4. **Run length:** 5 game minutes.

## Implementation notes

- **Balance.** The first layout (Mines on every ore, two Lumber Camps, a Stone Mine, and the Drill
  Rig) jammed about 7 minutes after loading: Iron Ore came far faster than three Smelters used it,
  Stone and the extra Wood had no use, and trucks with a load storage could not take waited at the
  HQ. The town now mines only what it uses; a 40-minute run shows no truck waiting until the
  Smelters' Iron and Copper fill the Cargo pool at about 35 minutes. `DemoTownTests` holds this
  for 15 minutes. Truck capacity and trucks waiting at the HQ with a load nothing can take are
  known issues for a later changeset; the demo should be rewritten after it.
- **Research.** There are only two projects, and finishing Material Transfer makes trucks
  unnecessary, so it starts from zero and finishes about 15 minutes after loading, not "a few
  projects done".
- **Exploring.** Sight around the spawn does not reach the whole town, so the builder walks the
  player over a grid around it before placing anything, then returns them to the spawn.
- **Network.** Small Hubs link at 12 units and cover 8, measured from their centers, so the town
  needed eleven, placed by hand along each branch.
- **Writing.** `--write-demo-save` loads the usual way (the views need the models and pictures),
  then opens the demo town as a loaded save with its pins and zoom, lets it draw for 30 frames, and
  writes the save with `MakeSave` and `CaptureThumbnail`. The game's own save path writes the
  presentation's part, so the demo keeps its pins and zoom.
- **Exports.** Godot leaves files it does not import out of a pack, so the presets include
  `assets/saves/*.save`; both Windows exports were checked to carry `demo.save` and `demo.png`.
  The release build was not launched to click Demo.

## Open questions (answered)

1. **How do you reach it?**
   - (a) A **Demo** button on the main menu that loads it from inside the game (`res://`). Saving
     from it makes a new named save, so the demo is never changed. Release builds have it too.
   - (b) The demo is copied into the saves folder the first time the game runs, so it appears in
     Load Game like any save (and can be saved over or deleted).
   - (c) A file only in the repo, which you copy into your saves folder by hand; not in builds.

   Proposed: (a).
2. **Include tier-1 power?** A Burner Generator and a Drill Rig show the powered tier, but the
   town is more than a mining town. Proposed: yes, just those two.
3. **Fixed layout with placed fields, or real deposits?** Placing the fields the layout needs
   makes the town the same whatever the generator does later, but those fields are not where the
   world put them. Finding real deposits near the spawn keeps the world honest, but the layout then
   depends on the seed and changes if the generator changes. Proposed: placed fields.
4. **How far into its run?** About 5 game minutes: enough for full buffers, trucks out, and a
   stockpile that moves, short of the first autosave. Proposed: 5 minutes.
