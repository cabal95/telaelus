# Terrain models

Models drawn by the terrain renderer (`TerrainTiles` and `MountainModels` in
`src/Game/Presentation/`). See `docs/blueprints/terrain.md` for the terrain model they draw.

## Mountains (required)

Generated by the asset factory (`src/asset-factory/tools/gen.py`, see `docs/asset-pipeline.md`).
The game loads these by name and throws if one is missing, so all six must be present.

| Ground beneath the mountain | Family | Files |
|---|---|---|
| Snow | Snow | `mountain_snow_a.glb`, `mountain_snow_b.glb`, `mountain_snow_c.glb` |
| Grass, Sand, Mud, Rock | Stone | `mountain_a.glb`, `mountain_b.glb`, `mountain_c.glb` |

- Both families use the same three shapes (a, b, c); only the coloring differs. Stone is bare
  rock; Snow is snow-covered with rock on the steep faces.
- One model fills one **map cell**: 4 x 4 world units, origin at the center of the base, resting
  on y = 0, Y up. It is placed unscaled, and nothing extends past the cell.
- Every edge of every variant lies flat on the ground (height 0), so each mountain is a
  standalone peak: it looks finished alone, and neighbors sit side by side as a cluster. Any
  variant can sit next to any other in any 90-degree rotation.
- The variant and a 90-degree rotation are chosen per map cell from its coordinates.
- Adding a family (for example sandstone for Sand) means three files plus a row in the
  `MountainModels` family table.

## Ground tiles (not yet modeled)

Terrain ground is still flat colored placeholder tiles, one color per terrain type, with edge
strips toward higher-priority neighbors (see the terrain blueprint). Models for ground tiles would
follow the same 4 x 4 map-cell scale.
